bila kubuni moduli mpya.

## 1. Teknolojia Zinazotumika

| Kipengele                | Chaguo                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Mfumo wa wavuti          | **Next.js 16** (App Router, matokeo yanayojitegemea, bila middleware ya jumla)                                                             |
| Lugha                    | **TypeScript 6.0+** — lengwa `ES2022`, `module: esnext`, `moduleResolution: bundler`, `strict: false`                                      |
| Mazingira ya utekelezaji | **Node.js** `>=22.22.2 <23` au `>=24.0.0 <27` (inatekelezwa kupitia `engines` + `SUPPORTED_NODE_RANGE`)                                    |
| Hifadhidata              | **SQLite** kupitia `better-sqlite3` (singleton, uandishi wa jarida wa WAL)                                                                 |
| Programu ya mezani       | **Electron 41** + `electron-builder` 26.10 (workspace tofauti katika `electron/`)                                                          |
| Majaribio                | **Kitekelezaji asili cha majaribio cha Node** (unit/integration), **Vitest** (MCP, autoCombo, cache), **Playwright** (e2e + protocols-e2e) |
| Ujenzi                   | Next.js inayojitegemea kupitia `scripts/build/build-next-isolated.mjs`                                                                     |
| Lint/uumbizaji           | Usanidi tambarare wa ESLint + Prettier (`lint-staged` kupitia Husky pre-commit)                                                            |
| Mfumo wa moduli          | ESM kila mahali (`"type": "module"`)                                                                                                       |
| UI ya dashibodi          | **Tailwind CSS 4** + **Keak CI UI Kit** iliyojumuishwa ndani (`packages/ui-kit`), ikoni za Lucide — tazama `DESIGN_SYSTEM.md`              |
| Workspaces               | npm workspaces — `open-sse`, `packages/browser-pool`, `packages/ui-kit`                                                                    |

Majina mbadala ya njia (`tsconfig.json`):

- `@/*` → `src/*`
- `@omniroute/open-sse` → `open-sse/index.ts`
- `@omniroute/open-sse/*` → `open-sse/*`
- `@omniroute/ui-kit` → `packages/ui-kit/src`, `@omniroute/ui-kit/*` → `packages/ui-kit/src/*`

Porti chaguomsingi ya HTTP: **`20128`** (API na dashibodi zinatumia mchakato uleule). Saraka ya
data ni env var ya `DATA_DIR`, na thamani yake chaguomsingi ni `~/.omniroute/`.

### 3.1 `src/app/` — App Router

App Router hutoa UI ya dashibodi pamoja na API ya HTTP ya umma/usimamizi.
Hakuna **middleware ya jumla** — kukatiza hufanywa kwa kila route.

Sehemu za kiwango cha juu chini ya `src/app/`:

| Njia                                                                          | Kusudi                                                            |
| ----------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `api/`                                                                        | Njia zote za API ya HTTP (tazama mgawanyo hapa chini)             |
| `a2a/`                                                                        | Endpoint ya A2A JSON-RPC 2.0 (`POST /a2a`)                        |
| `.well-known/agent.json/`                                                     | Hati ya ugunduzi wa A2A Agent Card                                |
| `(dashboard)/`                                                                | UI ya dashibodi (kikundi cha route, bila kiambishi awali cha URL) |
| `auth/`, `login/`, `forgot-password/`, `callback/`                            | Mtiririko wa uthibitishaji                                        |
| `landing/`                                                                    | Ukurasa wa umasishaji/landing                                     |
| `docs/`                                                                       | Kionyeshaji cha nyaraka za API kilichojumuishwa                   |
| `status/`, `maintenance/`, `offline/`                                         | Kurasa za uendeshaji                                              |
| `privacy/`, `terms/`                                                          | Kurasa za kisheria                                                |

#### 3.1.2a `src/app/api/services/` — Usimamizi wa Huduma Zilizojumuishwa

Njia za kusakinisha, kuzindua, kusitisha, na kufuatilia 9Router na CLIProxyAPI.
Njia zote zimeainishwa kama **LOCAL_ONLY** (loopback pekee, kanuni lazima #17) kwa sababu
zinaweza kuitisha `npm install` na kuzaa michakato ya watoto (child processes).

```
src/app/api/services/
├── 9router/
│   ├── _lib.ts             kisaidizi cha getOrInitSupervisor()
│   ├── install/route.ts    POST — npm install kupitia execFile
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — npm install toleo jipya
│   ├── rotate-key/route.ts POST — tengeneza ufunguo mpya wa API + anzisha upya
│   ├── status/route.ts     GET  — hali ya moja kwa moja + hali ya DB + metadata ya toleo
│   └── auto-start/route.ts POST — geuza bendera ya auto_start
├── cliproxy/
│   ├── _lib.ts             kisaidizi cha getOrInitSupervisor()
│   ├── install/route.ts    POST — npm install
│   ├── start/route.ts      POST — supervisor.start()
│   ├── stop/route.ts       POST — supervisor.stop()
│   ├── restart/route.ts    POST — supervisor.restart()
│   ├── update/route.ts     POST — npm install toleo jipya

└── [name]/
    └── logs/route.ts       GET  — mkia wa kumbukumbu wa SSE (unaposhirikiwa na huduma zote)
```

UI ya dashibodi inayohusiana:
`src/app/(dashboard)/dashboard/providers/services/` — ukurasa wa tabo mbili (CLIProxyAPI + 9Router).

`src/app/(dashboard)/dashboard/providers/services/[name]/embed/[[...path]]/route.ts`

Uchunguzi wa kina: `docs/frameworks/EMBEDDED-SERVICES.md`

## 10. Jinsi ya Kuchangia

### Ongeza mtoa huduma mpya

1. Sajili katika `src/shared/constants/providers.ts` (inathibitishwa na Zod wakati wa kupakia).
2. Ongeza kitekelezaji katika `open-sse/executors/` ikiwa mantiki maalum inahitajika

   `src/lib/oauth/services/`.
5. Sajili modeli katika `open-sse/config/providerRegistry.ts` (au sajili mahususi ya
   umbizo chini ya `open-sse/config/`).
6. Andika majaribio chini ya `tests/unit/`.

### Ongeza njia mpya ya API

1. Unda `src/app/api/your-route/route.ts`.
2. Fuata mpangilio huu: CORS → uthibitishaji wa body kwa Zod → uthibitishaji wa utambulisho → ukabidhi kwa handler.
3. Ikiwa ni muundo mpya wa ombi: ongeza schema ya Zod katika `src/shared/validation/schemas.ts`.
4. Ikiwa ni ya usimamizi pekee: ongeza path kwenye `src/shared/constants/publicApiRoutes.ts`
   (orodha ya kukataa kwa sehemu ya API ya umma).
5. Ongeza majaribio chini ya `tests/unit/`.
6. Sasisha `docs/reference/API_REFERENCE.md` na `docs/openapi.yaml`.

### Ongeza moduli mpya ya DB

1. Unda `src/lib/db/yourModule.ts` na uingize `getDbInstance()` kutoka `./core.ts`.
2. Hamisha vitendakazi vya CRUD kwa ajili ya kikoa chako.
3. Ikiwa kuna majedwali mapya: ongeza uhamishaji chini ya `src/lib/db/migrations/`, uliowekewa nambari
   kwa mfuatano, unaoweza kurudiwa bila athari za ziada, na wa kimuamala.
4. Waingizaji watumie uingizaji wa moja kwa moja kutoka `@/lib/db/yourModule` (bila barrel — safu ya zamani ya kusafirisha upya ya `localDb.ts` iliondolewa).

### Ongeza zana mpya ya MCP

1. Ongeza ufafanuzi wa zana chini ya `open-sse/mcp-server/tools/` (au panua
   `open-sse/mcp-server/schemas/tools.ts`).
2. Weka scope husika katika `src/shared/constants/mcpScopes.ts`.
3. Sajili zana katika `open-sse/mcp-server/server.ts`.
4. Ongeza majaribio chini ya `open-sse/mcp-server/__tests__/`.

## 11. Kanuni

- **Mtindo wa msimbo**: ujongezaji wa nafasi 2, alama mbili za kunukuu, upana wa herufi 100, semikoni,
  koma za mwisho za `es5` — hutekelezwa na Prettier kupitia `lint-staged`.
- **Uingizaji**: wa nje → wa ndani (`@/`, `@omniroute/open-sse`) → wa jamaa.
- **Utoaji majina**: faili `camelCase` au `kebab-case`, vijenzi `PascalCase`,
  konstanti `UPPER_SNAKE`.
- **ESLint**: `no-eval`, `no-implied-eval`, `no-new-func` = `error` kila mahali;
  `no-explicit-any` = `warn` katika `open-sse/` na `tests/`, error kwingineko.
- **TypeScript**: `strict: false` (msimamo wa mifumo ya zamani). Pendelea aina zilizobainishwa wazi kuliko
  uainishaji wa kiotomatiki katika mipaka ya moduli.
- **Hifadhidata**: kamwe usiandike SQL ghafi katika njia au handler — kila mara pitia
  moduli za `src/lib/db/`. Kamwe usiingize kupitia barrel — tumia moja kwa moja moduli mahususi za `src/lib/db/*`.
- **Uainishaji wa huluki za DB (#3512)**: kitendakazi kinachoandika au kusoma muundo wa
  safu ya jedwali la DB kinapaswa kupokea/kurejesha interface ya TS yenye jina inayoakisi
  safu wima za jedwali hilo 1:1, si `any` au aina isiyo na jina iliyoandikwa moja kwa moja mahali pa kuitwa. Weka
  interface karibu na kitendakazi (k.m. `export interface UsageEntry` katika
  `src/lib/usage/usageHistory.ts` juu ya `saveRequestUsage`), acha sehemu binafsi
  ziwe za hiari/zinazokubali null wakati waandishi tofauti hujaza safu
  hatua kwa hatua, na pendelea `unknown` kuliko `any` kwa sehemu ambayo muundo wake
  hutofautiana kulingana na mwitaji (imeandikwa katika sehemu hiyo, k.m. `UsageEntry.tokens`
  inakubali matumizi ghafi yenye muundo wa mtoa huduma na pia muundo uliosanifishwa). Mara tu idadi ya
  `any` katika faili inapofikia sifuri kwa njia hii, iongeze kwenye orodha ya kuruhusu ya
  `check:any-budget:t11` (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`) ili hali hiyo isirudi nyuma. Hii ni kanuni ya sehemu ya kwanza — usafishaji mpana zaidi wa
  "hakuna `any` isiyo na jina" unafanywa kwa hatua katika sehemu nyingine za codebase.
- **Hitilafu**: tumia try/catch yenye aina mahususi za hitilafu, na urekodi kwa muktadha wa pino. Kamwe
  usipuuze hitilafu kimya kimya katika mitiririko ya SSE; tumia ishara za kusitisha kwa ajili ya usafishaji.
- **Usalama**: kamwe usitumie `eval()` / `new Function()` / eval isiyo ya moja kwa moja. Thibitisha
  ingizo zote kwa Zod. Simba vitambulisho vinapohifadhiwa (AES-256-GCM). Weka
  orodha ya kukataa ya `src/shared/constants/upstreamHeaders.ts` ikiwa imelandanishwa na
  safu ya usafishaji/uthibitishaji.
- **Commit**: Conventional Commits — `feat(scope): subject`. Scope zinazoruhusiwa:
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`.
- **Branch**: viambishi awali `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`. Kamwe usifanye commit moja kwa moja kwenye `main`.
- **Husky**: pre-commit huendesha `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11`; pre-push huendesha `check:any-budget:t11` + `check:tracked-artifacts` (vizuizi vya haraka; haijumuishi `test:unit`).
