> **خلاصہ**: OmniRoute اپنے **مفت** فراہم کنندگان کو ماڈل کے معیار کے لحاظ سے **Arena AI
> (LMArena طرز کے) ELO اسکورز** استعمال کرتے ہوئے درجہ دیتا ہے۔ ڈیش بورڈ میں **مفت فراہم کنندگان کی درجہ بندی** کا صفحہ کھولیں تاکہ معلوم ہو سکے کہ کون سے مفت فراہم کنندگان آپ کے کام کے لیے مضبوط ترین ماڈلز فراہم کرتے ہیں —
> مجموعی طور پر، یا زمرے کے لحاظ سے فلٹر کر کے (کوڈنگ، جائزہ، دستاویزات، ڈی بگنگ)۔

## یہ کیا ہے

OmniRoute میں 376 پرووائیڈرز رجسٹرڈ ہیں، جن میں 155 کیٹلاگ اندراجات **مفت/بغیر-تصدیق (free/no-auth)** کے نشان والے شامل ہیں
(no-auth،
free-tier OAuth، یا free-tier API key — دیکھیں
[مفت درجوں کی رہنما](../getting-started/FREE-TIERS-GUIDE.md) اور مکمل
[Free Tiers ڈائریکٹری](../reference/FREE_TIERS.md))۔ البتہ مسئلہ یہ ہے: مفت پرووائیڈرز ماڈل کے معیار میں
بہت زیادہ فرق رکھتے ہیں۔ ایک فرنٹئیر ماڈل پیش کرنے والا no-auth پرووائیڈر اس پرووائیڈر کی نسبت کہیں زیادہ مفید ہے
جو کوئی چھوٹا پرانا ماڈل پیش کرتا ہے۔

**Free Provider Rankings** اس سوال کا جواب دیتا ہے کہ "**کون سا مفت پرووائیڈر مجھے بہترین ماڈل دیتا ہے؟**"
یہ ہر مفت پرووائیڈر کے کیٹلاگ کو **Arena AI لیڈر بورڈ** کے **کروڈ-سورسڈ معیاری اسکورز** کے ساتھ
جوڑ کر کرتا ہے (انسانی-ترجیح پر مبنی ELO، وہی تصور جو LMArena
چیٹ بوٹ ارینا کے پیچھے ہے)۔ اس کے بعد پرووائیڈرز کو ان کے **بہترین مفت ماڈل** کی طاقت کی بنیاد پر درجہ بند کیا جاتا ہے۔

یہ درجہ بندی تین حقیقی ذرائع سے تیار کی جاتی ہے:

1. مفت پرووائیڈرز کی فہرستیں — `NOAUTH_PROVIDERS`، نیز `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` کے وہ اندراجات جن پر `hasFree` کا جھنڈا لگا ہوا ہے
   (`src/shared/constants/providers.ts`)۔
2. ہر پرووائیڈر کا ماڈل کیٹلاگ، پرووائیڈر رجسٹری سے
   (`open-sse/config/providerRegistry.ts`)۔
3. ELO سے ماخوذ ٹاسک-فٹ اسکورز، جو `model_intelligence` DB ٹیبل میں
   Arena ELO سنک انجن (`src/lib/arenaEloSync.ts`) کے ذریعے محفوظ کیے جاتے ہیں۔

جوائن کی منطق `src/lib/freeProviderRankings.ts` میں موجود ہے۔

## رسائی کا طریقہ

### ڈیش بورڈ صفحہ

ڈیش بورڈ کھولیں اور **لاگتیں → مفت فراہم کنندگان کی درجہ بندی** پر جائیں، یا براہِ راست یہاں جائیں:

```
/dashboard/free-provider-rankings
```

یہ صفحہ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) درج ذیل دکھاتا ہے:

- بہترین درجہ رکھنے والے مفت فراہم کنندگان کے لیے **سرفہرست 3 کا پوڈیم** (🥇 🥈 🥉)۔
- ایک مکمل **درجہ بندی کی جدول**، جس کے کالم ہیں: **درجہ**، **فراہم کنندہ**، **بہترین ماڈل**،
  **اسکور**، **اوسط اسکور**، **ماڈلز**، **قسم**۔
- **زمرہ فلٹر بٹنز**: _تمام زمرے_، _ڈیفالٹ_، _کوڈنگ_، _جائزہ_،
  _دستاویزات_، _ڈی بگنگ_۔

ہر فراہم کنندہ کا **قسم** بیج بتاتا ہے کہ وہ کس طرح مفت ہے:

| بیج      | مطلب                                              |
| -------- | ------------------------------------------------- |
| `NOAUTH` | ہمیشہ مفت، کسی اسناد کی ضرورت نہیں                |
| `OAUTH`  | مفت درجے (`hasFree`) کے ساتھ OAuth فراہم کنندہ    |
| `APIKEY` | مفت درجے (`hasFree`) کے ساتھ API کلید فراہم کنندہ |

اسکورز خام اعداد کے بجائے انسانی طور پر قابلِ فہم لیبلز کی صورت میں دکھائے جاتے ہیں (مثلاً _اعلیٰ ترین_، _شاندار_، _بہت اچھا_،
_اچھا_، _اوسط_)، کیونکہ بنیادی قدر فیصد نہیں بلکہ معیار کی نسبتی
درجہ بندی ہے۔

### API اینڈ پوائنٹ

یہ صفحہ ایک عوامی، صرف پڑھنے کے اینڈ پوائنٹ
(`src/app/api/free-provider-rankings/route.ts`) سے تقویت پاتا ہے:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

استفساری پیرامیٹرز (Zod کے ذریعے توثیق شدہ):

| پیرامیٹر   | قسم    | ڈیفالٹ      | نوٹس                                                                                                              |
| ---------- | ------ | ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `category` | اسٹرنگ | (کوئی نہیں) | `default`، `coding`، `review`، `documentation`، `debugging` میں سے ایک۔ مشترکہ درجہ بندی کے لیے اسے شامل نہ کریں۔ |
| `limit`    | عدد    | `50`        | `1–100` کی حد تک محدود کیا جاتا ہے۔                                                                               |

جواب کی ساخت:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` اصل Arena ELO قدر ہے؛ `score` معمول پر لائی گئی کام سے مطابقت کی قدر ہے
(ذیل میں ملاحظہ کریں)۔ جن فراہم کنندگان کے کسی ماڈل کا اسکور موجود نہ ہو، انہیں جواب سے خارج کر دیا جاتا ہے۔

## اسکورز کیسے کام کرتے ہیں

### ماخذ: Arena AI لیڈر بورڈ

Arena ELO سنک انجن (`src/lib/arenaEloSync.ts`) Arena AI لیڈر بورڈ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) سے دو لیڈر بورڈز — `text`
اور `code` — حاصل کرتا ہے۔ جب یہ API کوئی قابلِ استعمال بورڈ واپس نہیں کرتا، تو انجن
Hugging Face datasets-server پر موجود باضابطہ `lmarena-ai/leaderboard-dataset`
(`src/lib/arenaEloHfSource.ts`، CC-BY-4.0؛ `overall` → `text`،
`coding` → `code`) استعمال کرتا ہے؛ `GET /api/intelligence/sync` میں `activeSource`، `lastError`
اور `lastFailedAt` رپورٹ کیے جاتے ہیں۔ ہر لیڈر بورڈ اندراج میں
ماڈل کا نام، وینڈر، ELO `score`، اعتماد کا وقفہ، اور ووٹس کی تعداد شامل ہوتی ہے۔

لیڈر بورڈ کے زمرے OmniRoute کے ٹاسک زمروں سے یوں منسلک ہوتے ہیں:

| Arena لیڈر بورڈ | OmniRoute ٹاسک زمرے                               |
| --------------- | ------------------------------------------------- |
| `text`          | `default`، `review`، `documentation`، `debugging` |
| `code`          | `coding`                                          |

### نارملائزیشن (ٹاسک موزونیت اسکور)

خام ELO اسکورز کو ہر لیڈر بورڈ کے لیے نارملائز کر کے **`[0.4, 0.98]` میں ٹاسک موزونیت کی قدر** بنایا جاتا ہے:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

اسکور کبھی `0` یا `1` تک نہیں پہنچتا، جس سے صارف کی جانب سے اوور رائیڈز کے لیے گنجائش باقی رہتی ہے۔
یہی وہ `score` فیلڈ ہے جو آپ API رسپانس میں دیکھتے ہیں اور یہی لیبل ڈیش بورڈ پر دکھایا جاتا ہے۔

### اعتماد

ہر اندراج کو Arena ووٹس کی تعداد کی بنیاد پر اعتماد کی ایک سطح دی جاتی ہے:

| اعتماد   | ووٹس    |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### اسٹوریج اور تازگی

نارملائز کردہ اندراجات `model_intelligence` DB ٹیبل میں
`source = "arena_elo"` کے ساتھ لکھے جاتے ہیں (`src/lib/db/modelIntelligence.ts`)۔ اندراجات کی میعاد
**7 دن بعد ختم ہو جاتی ہے**، لہٰذا جو پرووائیڈر سنک ہونا بند کر دے وہ پرانا ڈیٹا فراہم کرنے کے بجائے
بالآخر فہرست سے نکل جاتا ہے۔

سنک **بطور ڈیفالٹ فعال** ہوتا ہے:

- یہ سرور اسٹارٹ اپ پر ایک بار اور پھر ایک وقفہ وار ٹائمر کے مطابق چلتا ہے
  (`src/lib/arenaEloSync.ts`، جسے `src/instrumentation-node.ts` سے منسلک کیا گیا ہے)۔
- یہ **نان بلاکنگ ہے اور کبھی بھی مہلک نہیں ہوتا** — اگر اپ اسٹریم فیچ ناکام ہو جائے تو OmniRoute
  چلتا رہتا ہے اور رینکنگز صرف آخری درست ڈیٹا (یا ایک خالی حالت) دکھاتی ہیں۔

اسے دو انوائرنمنٹ ویری ایبلز کنٹرول کرتے ہیں (جن کی دستاویز
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) میں موجود ہے):

| ویری ایبل                 | ڈیفالٹ        | مقصد                                                           |
| ------------------------- | ------------- | -------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | آؤٹ باؤنڈ سنک سے دستبردار ہونے کے لیے اسے `false` پر سیٹ کریں۔ |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | سنک کا وقفہ، سیکنڈز میں۔                                       |

### دستی سنک / اسٹیٹس / کلیئر

آپریٹرز کے لیے، ایک تصدیق شدہ مینجمنٹ اینڈ پوائنٹ دستی کنٹرول فراہم کرتا ہے
(`src/app/api/intelligence/sync/route.ts` — مینجمنٹ توثیق درکار ہے):

```
GET    /api/intelligence/sync          # موجودہ سنک اسٹیٹس (enabled، lastSync، nextSync، intervalMs)
POST   /api/intelligence/sync          # دستی سنک شروع کریں؛ لکھے بغیر پیش منظر کے لیے باڈی: { "dryRun": true }
DELETE /api/intelligence/sync          # تمام سنک شدہ arena_elo انٹیلیجنس اندراجات صاف کریں
```

اگر رینکنگز کا صفحہ خالی ہو، تو دستی `POST /api/intelligence/sync` (یا صرف
سرور کو دوبارہ شروع کرنا) اسے دوبارہ آباد کر دیتا ہے۔

### ماڈلز کو لیڈر بورڈ سے ملانا

رجسٹری ماڈل IDs اور Arena ماڈل نام ہمیشہ بالکل یکساں نہیں ہوتے۔ رینکنگ
لچک دار میچنگ استعمال کرتی ہے (`src/lib/freeProviderRankings.ts` میں `findMatchingIntelligence`):

1. نارملائز کردہ ماڈل ID پر عین مماثلت۔
2. آخر میں موجود ورژن سفکس ہٹانے کے بعد مماثلت (مثلاً `kimi-k2.6` → `kimi-k2`)۔
3. پریفکس مماثلت (لیڈر بورڈ ماڈل کا نام رجسٹری ID کا پریفکس ہو)۔

سنک کی جانب، معلوم وینڈر پریفکسز (`anthropic/`، `openai/`، `google/`، …)
ہٹا دیے جاتے ہیں اور ایک چھوٹا عرفی نقشہ بنیادی ناموں کو ان مختلف صورتوں میں پھیلاتا ہے جنہیں OmniRoute
اندرونی طور پر استعمال کرتا ہے، تاکہ ماڈلز کسی بھی نام سے قابلِ تلاش رہیں۔

### کسی پرووائیڈر کی رینکنگ کیسے ہوتی ہے

ہر مفت پرووائیڈر کے لیے، انجن اس کے کیٹلاگ میں موجود ہر ماڈل کو اسکور کرتا ہے، پھر:

- **بہترین ماڈل** = پرووائیڈر کا سب سے زیادہ اسکور رکھنے والا ماڈل۔
- **اوسط اسکور** = اس پرووائیڈر کے تمام اسکور شدہ ماڈلز کے اسکورز کا اوسط۔
- **ماڈلز** = پرووائیڈر کے کتنے ماڈلز کے لیے Arena اسکور دستیاب تھا۔

پرووائیڈرز کو پہلے **بہترین ماڈل کے اسکور** اور پھر اوسط اسکور کے لحاظ سے ترتیب دیا جاتا ہے۔ اس طرح
کم از کم ایک مضبوط مفت ماڈل فراہم کرنے والے پرووائیڈر کو فائدہ ملتا ہے۔

## مفت فراہم کنندگان منتخب کرنے کے لیے اس کا استعمال

1. **درست زمرہ منتخب کریں۔** ایجنٹ پر مبنی/کوڈ ورک لوڈز کے لیے **کوڈنگ** فلٹر استعمال کریں، یا
   عمومی چیٹ کے لیے اسے **تمام زمرے** / **ڈیفالٹ** پر رہنے دیں۔ ایک ہی فراہم کنندہ
   مختلف زمروں میں مختلف درجہ حاصل کر سکتا ہے، کیونکہ ہر لیڈر بورڈ پر اس کا سرفہرست ماڈل مختلف ہوتا ہے۔
2. **ایک مرتبہ کی سیٹ اپ کے لیے پوڈیم کو ترجیح دیں۔** اگر آپ صرف ایک یا دو مفت
   فراہم کنندگان سے جڑنا چاہتے ہیں، تو اپنے زمرے میں سرفہرست درجہ رکھنے والوں سے آغاز کریں۔
3. **قسم کا بیج چیک کریں۔** `NOAUTH` فراہم کنندگان سے جڑنا سب سے تیز ہے (کسی
   اسناد کی ضرورت نہیں)۔ `OAUTH` / `APIKEY` کے مفت درجات کے لیے فوری سائن اپ درکار ہوتا ہے، لیکن اکثر یہ
   زیادہ طاقتور ماڈلز تک رسائی فراہم کرتے ہیں۔ کنکشن کے مراحل کے لیے [مفت درجات کی گائیڈ](../getting-started/FREE-TIERS-GUIDE.md)
   دیکھیں۔
4. **متعدد فراہم کنندگان سے جڑیں اور Auto-Combo کو فیصلہ کرنے دیں۔** Arena ELO کا وہی ڈیٹا جو
   اس صفحے کو تقویت دیتا ہے، Auto-Combo اسکورنگ انجن کے **کام کے لیے موزونیت کے عامل** کو بھی فراہم کیا جاتا ہے
   (`open-sse/services/autoCombo/taskFitness.ts`، ترجیحی ترتیب
   `user_override → arena_elo → models_dev_tier → static table`)۔ لہٰذا سرفہرست مفت فراہم کنندگان سے جڑنے کے بعد،
   `model: "auto"` (مثلاً `auto/coding`) کے ساتھ روٹنگ ہر درخواست کے لیے
   خودکار طور پر اعلیٰ معیار کے مفت ماڈلز کو ترجیح دے گی۔ مکمل 16 عاملی اسکورنگ کے لیے
   [Auto-Combo](../routing/AUTO-COMBO.md) دیکھیں۔
