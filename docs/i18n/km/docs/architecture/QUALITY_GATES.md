## បញ្ជីសារពើភ័ណ្ឌ gate និង profile ការប្រតិបត្តិ

### ការទទួលយកបេក្ខជន

Workflow CI និង Quality Gates នីមួយៗបញ្ចេញការវិនិច្ឆ័យដែលមានស្ថេរភាព៖ `Gate / CI` និង
`Gate / Quality`។ គោលនយោបាយទទួលយកដែលមានកំណែរបស់ពួកវារាប់បញ្ជី job ខាងលើទាំងអស់
ជា required ឬ advisory។ job required ដែលអនុវត្តបានត្រូវតែជោគជ័យ៖ លទ្ធផល missing,
cancelled, skipped, pending និង unknown មិនអាចបង្កើត PASS បានទេ។ ការចាត់ថ្នាក់ docs-only
ឬ catalog-only ដែលត្រឹមត្រូវអាចធ្វើឱ្យ lane កូដមិនអនុវត្តបាន។
PR ដែលជា draft មិនមែនជាបេក្ខជនដែលត្រូវបានទទួលយកទេ។ label `hotfix` មិនលើកលែងភស្តុតាងទេ។

Workflow ទាំងពីរគ្របដណ្តប់ PR ចូលទៅ branch main/release, push ទៅ `main`, dispatch ដោយដៃ
និង event merge-group។ Push, dispatch និង merge-group ដំណើរការជម្រើសពេញលេញ។ Push ទៅ
`release/**` មិនចាប់ផ្តើមពួកវាទេ (2026-10-18)៖ ការផ្លាស់ប្តូរនីមួយៗបានដំណើរការ matrix លើ PR របស់វារួចហើយ
ហើយបណ្តុំដែលបានបញ្ចូលគ្នាគឺជាការងាររបស់ Release-Green (`docs/ops/RUNNER_BOX.md` → Hosted lane)។ Fork
និង merge group ប្រើ hosted runner សម្រាប់ job ដែលជាធម្មតាជ្រើសរើស self-hosted
runner៖ សមត្ថភាព hosted គ្រប់គ្រាន់ត្រូវតែផ្ទៀងផ្ទាត់មុនពេល rollout។

receipt JSON នីមួយៗកំណត់អត្តសញ្ញាណ SHA ដែលបាន checkout, ការដំណើរការ workflow និង attempt។
CLI បដិសេធការមិនត្រូវគ្នានៃ SHA រវាង checkout/event។ ការធ្វើតេស្ត workflow ចងសមាជិកភាពគោលនយោបាយ
ទៅនឹងបញ្ជី `needs` របស់ job វិនិច្ឆ័យ ដើម្បីឱ្យ lane ថ្មី ឬដែលបានដកចេញមិនអាចបាត់ទៅដោយស្ងៀមស្ងាត់បាន។
receipt ទាំងនេះគ្របដណ្តប់តែ workflow របស់ពួកវាផ្ទាល់ មិនមែនការផ្សព្វផ្សាយ ការដាក់ប្រើប្រាស់ ឬផ្នែកខាងក្នុង
របស់ advisory scanner ដែលមានស្រាប់ទេ។ ការធ្វើឱ្យសកម្មឈ្មោះ check ទាំងពីរនៅក្នុង branch rule គឺជា
ការផ្លាស់ប្តូររដ្ឋបាលដាច់ដោយឡែក៖ ការបន្ថែម job ទាំងនេះមិនការពារ branch ដោយខ្លួនឯងទេ។

### បញ្ជីសារពើភ័ណ្ឌស្កេនស្ថិតិ

បញ្ជីសារពើភ័ណ្ឌ npm-alias ដែលមានកំណែ និងសមាជិកភាពស្កេនស្ថិតិស្ថិតនៅក្នុង
`config/quality/gate-manifest.json`។ ដំណើរការ `npm run check:gate-manifest` ដើម្បីផ្ទៀងផ្ទាត់
ឈ្មោះ script និងពាក្យបញ្ជាពិតប្រាកដប្រៀបធៀបនឹង `package.json`៖ ការបន្ថែម ការដកចេញ និង
ការវង្វេងពាក្យបញ្ជាធ្វើឱ្យ local hook និង job ចាត់ថ្នាក់ការផ្លាស់ប្តូរក្នុង CI បរាជ័យទាំងពីរ។
alias មិនមែនជា workflow job, matrix instance ឬ test case ទេ៖ ចំនួនទាំងនេះត្រូវតែ
មិនបង្ហាញថាអាចប្តូរគ្នាបាន។

ប្រើ `npm run quality:scan -- --list` ឬ `npm run quality:scan:fast -- --list`
ដើម្បីពិនិត្យ alias ដែលបានជ្រើសរើសដោយមិនប្រតិបត្តិពួកវា។ runner ហៅ
npm entrypoint ដូច្នេះ runtime របស់វា (រួមទាំង Bun កន្លែងដែលបានកំណត់រចនាសម្ព័ន្ធ) ត្រូវបានរក្សាទុក។
manifest កត់ត្រា alias ដែលនៅក្រៅ profile ទាំងនោះថាត្រូវបានហៅដោយឡែក ហើយ
ពាក្យបញ្ជាថែទាំត្រូវបានហាមឃាត់ក្នុង profile ស្កេនអានតែប៉ុណ្ណោះ។

profile ទាំងនេះគ្របដណ្តប់តែស្កេនស្ថិតិប៉ុណ្ណោះ។ ពួកវាមិនបញ្ជាក់ការធ្វើតេស្តផលិតផល
ការគ្របដណ្តប់ ការវេចខ្ចប់ ការពិនិត្យខាងក្រៅ ឬការទទួលយកការចេញផ្សាយពេញលេញរបស់បេក្ខជនទេ។
ការទទួលយក workflow ប្រើ `config/quality/admission-policy.json` ដែលបានភ្ជាប់ និង
`scripts/quality/admission-verdict.mjs`។ profile Release-observer នៅតែដាច់ដោយឡែក៖
ពិនិត្យការពិនិត្យដែលអនុវត្តបាន និង receipt របស់ពួកវាដោយឯករាជ្យ។ បញ្ជីសារពើភ័ណ្ឌ
ជាអក្សរខាងក្រោមគឺជាឯកសារយោង មិនមែនជាភស្តុតាងថា gate បានដំណើរការពិតប្រាកដទេ។

script ស្ថិតនៅក្រោម `scripts/check/` (policy gate) និង `scripts/quality/` (ratchet engine)។
ប្រភពពិតនៃ CI គឺ `.github/workflows/ci.yml`។

### Release PR fast-path (`quality.yml`)

`.github/workflows/quality.yml` បំពេញបន្ថែម CI លើ PR main/release, push ទៅ `main`,
dispatch និង merge group។ PR ប្រើការពិនិត្យលឿនដែលចម្រោះតាម path។ build ស្ទួន
ដែលបានបិទជាអចិន្ត្រៃយ៍ត្រូវបានដកចេញ៖ ការពិនិត្យ build/package/boot ពិតប្រាកដនៅតែស្ថិតក្នុង CI។
unit suite និង vitest ដំណើរការតែក្នុង CI ប៉ុណ្ណោះ (`Unit Tests (N/8)`, `Vitest`)៖
job `Unit Tests fast-path` និង `Vitest (fast-path)` ពីមុនបានធ្វើពាក្យបញ្ជាដដែលម្តងទៀតលើ PR គ្រប់មួយ
នៅពេលដែល CI ចាប់ផ្តើមដំណើរការលើ release PR ហើយត្រូវបានដកចេញនៅថ្ងៃទី 2026-10-26។

| Job                                              | Scope                                                                                                                                                                                                       | Blocking          |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| `Docs Gates (fast-path)`                         | PR ឯកសារ/កូដ៖ API docs ref និង docs-all                                                                                                                                                                     | មាន               |

បេក្ខភាពនីមួយៗត្រូវបានផ្ទៀងផ្ទាត់ជាមួយស្ថានភាព gate ជាក់ស្តែងនៅថ្ងៃទី 2026-06-17 (ទុកចិត្ត ប៉ុន្តែត្រូវផ្ទៀងផ្ទាត់);
ការបញ្ចូលគ្នាដែលមើលទៅ "ជាក់ស្តែង" មួយចំនួន បែរជាលាក់បំណុល ហើយ **មិនមែន** ជាការជំនួសដោយផ្ទាល់ដែលគ្មានបញ្ហាទេ។

- **`check:docs-sync` ដំណើរការពីរដង** — ដាច់ដោយឡែកនៅក្នុង job `lint` និងម្តងទៀតនៅក្នុង `check:docs-all` (`docs-sync-strict`) ព្រមទាំង husky pre-commit hook។ ✅ **រួចរាល់** — invocation ដាច់ដោយឡែកក្នុង `lint` ត្រូវបានដកចេញ។
- **ការស្កេន CVE** — ❌ **មិនមែនជាការបញ្ចូលគ្នាដែលគ្មានបញ្ហាទេ។** `audit:deps` បរាជ័យភ្លាមៗលើ CVE កម្រិត high/critical ណាមួយ; `check:vuln-ratchet` (osv) បរាជ័យតែលើ _ការធ្លាក់ចុះ_ ធៀបនឹង baseline ប៉ុណ្ណោះ (បច្ចុប្បន្នមាន 1 MODERATE)។ អត្ថន័យខុសគ្នា — ការលុប `audit:deps` នឹងធ្វើឱ្យបាត់បង់ gate ដាច់ខាតសម្រាប់កម្រិត high/critical។ រក្សាទុកទាំងពីរ។
- **ការរកឃើញវដ្ត** — ✅ **រួចរាល់** (#15159 G-01/G-02)។ អត្ថបទចាស់នៅទីនេះបានហៅ `check:cycles` ថាជា gate "ពណ៌បៃតង ដែលបានជ្រើសរើសយ៉ាងប្រុងប្រយ័ត្ន" និងបានលើកហេតុផលឱ្យរក្សាវាជា blocking ព្រោះ `check:circular-deps` (dpdm) បានរាយការណ៍វដ្តចំនួន 91។ ស្ថានភាពពណ៌បៃតងនោះគឺជា **ភាពវិជ្ជមានក្លែងក្លាយ**៖ `check:cycles` បានស្កេនថតរងចំនួន 5 (450 files), ផ្គូផ្គងតែ `import|export … from` បែប static ហើយបានបោះបង់រាល់ specifier `@/` និង `@omniroute/open-sse/` ដូច្នេះវាមិនអាចមើលឃើញវដ្ត dynamic-import + alias ដែលមានច្រើនជាងគេក្នុង repo បានទេ។ បានកែរួច៖ ឥឡូវ gate ដើរឆ្លងកាត់ `src` + `open-sse` (5023 files), ប្រមូល specifier ពី TypeScript AST (ដូច្នេះ `import("…")` ត្រូវបានរាប់ ខណៈ `typeof import("…")` នៅទីតាំង type មិនត្រូវបានរាប់) ហើយ resolve `paths` របស់ tsconfig។ វារកឃើញវដ្តចំនួន **14** មិនមែន 0 ទេ។ ដោយសារវដ្តដែលមានស្រាប់ចំនួន 14 មិនអាចត្រូវបានជួសជុលនៅក្នុង gate PR បាន `check:cycles` ឥឡូវនេះគឺជា **ratchet** (`--ratchet`, ពិដាន `metrics.cycles.value = 14` ក្នុង `quality-baseline.json`, `direction: down`) — វារារាំង _ការធ្លាក់ចុះ_ ណាមួយ ហើយចំនួននេះអាចតែថយចុះប៉ុណ្ណោះ។ CI ដំណើរការ `npm run check:cycles:ratchet`។ ការកាត់បន្ថយជាបន្តបន្ទាប់ទៅជាមួយ **A-01**។ `check:circular-deps` (dpdm) នៅតែជាការណែនាំក្នុងនាមជាមតិទីពីរដែលទូលំទូលាយជាង។
- **ភាពស្មុគស្មាញ** — ✅ **រួចរាល់** (`check:complexity-ratchets` / `eslint.complexity-ratchets.config.mjs`)៖ ការដើរឆ្លងកាត់ ESLint មួយដង រាប់តាម ruleId ដើម្បីឱ្យ baseline របស់ cyclomatic+max-lines និង cognitive នៅដាច់ពីគ្នា; `check:complexity` / `check:cognitive-complexity` រៀងៗខ្លួននៅតែរក្សាទុកសម្រាប់ `--update` នៅមូលដ្ឋាន។
